# Отчёт: токены, стык страниц и дубли задач

Дата: 23.11.2026

## Что изменено

- У разобранного PDF появилось поле `token_usage` (`prompt_tokens`, `completion_tokens`, `total_tokens`). Расход читается из `completion.usage`, пишется в лог и показывается рядом с бейджем LLM и в «Подробностях» (`3 840 ток.`). Старые дела без этого поля бейдж не рисуют.
- Пример JSON в запросе к модели сериализуется без отступов. Повторы между системной инструкцией и правилами ответа убраны. Запрет выдумывать факты, правила дат, цитат, ФИО и отсечения шаблона сохранены.
- Цитата, которая начинается на одной странице и заканчивается на следующей, считается найденной. Ложное «⚠ проверить текст» на таком стыке не ставится.
- Срок с той же цитатой или с тем же сроком и той же сутью, что уже есть в поручении с исполнителем, в `deadlines` не дублируется.
- Первая фраза сводки больше не склоняет название суда: `Дело № … (Арбитражный суд …, судья …):`. Связки `ст. 213.4, 213.9 ФЗ-127` и `ст. 65, 223 АПК РФ` становятся одной ссылкой.

## Проверки

Команда из `backend`:

`.\.venv\Scripts\python.exe -c "import tests.test_ai_sanitizer as a, tests.test_sprint3 as b; ..."`

Результат: `ok` (17 тестов).

Проверено кодом: цитата со стыка стр. 1 и 2 остаётся `verified`; дубль «представить кандидатуру» остаётся только в поручении СРО, жалоба с другим текстом не удаляется; `3200 + 640` читаются как `total_tokens=3840`.

## Риски

- Уже сохранённые акты не получат `token_usage`, пока PDF не загрузят снова.
- Дедупликация срабатывает на новых разборах. Старые пары «поручение + срок» в базе остаются, пока акт не перезагружен.
- Совпадение по сроку требует ещё и общей сути текста. Два разных действия с одинаковым `days_limit` не схлопываются.

Открыть А21-11942/2026 и обновить страницу с `app.js?v=6`. Сводка должна начинаться с «Дело № А21-11942/2026 (Арбитражный суд…». После новой загрузки PDF рядом с бейджем LLM появится расход токенов.
